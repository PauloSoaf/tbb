# Demo Mode NutriOpus

> Data: 2026-07-05 · Agente: Claude (Fable)

## O que é

Demonstração interativa e pública do NutriOpus, acessível pelo site principal ("Ver demo interativa" no hero, "Demo" no header e CTA final). O visitante explora o painel da nutricionista e o portal do paciente **sem login, sem banco e sem backend** — tudo com dados fictícios.

## Rotas

| Visão | Rotas |
|---|---|
| Entrada | `/demo` (redireciona para o dashboard) |
| Nutricionista | `/demo/dashboard`, `/pacientes`, `/pacientes/[id]`, `/pacientes/[id]/avaliacoes`, `/pacientes/[id]/planos`, `/agenda`, `/atendimentos`, `/ferramentas` |
| Paciente | `/demo/portal`, `/cardapio`, `/evolucao`, `/diario`, `/compras`, `/chat`, `/agenda` |

## Garantias

- **Zero backend**: nenhuma página demo importa Prisma, Supabase, server actions ou APIs reais — todas são client components alimentadas por `src/demo/demo-data.ts`.
- **Sem sessão real**: nenhum cookie de auth é lido ou escrito; demo e app real não se misturam.
- **Badge DEMO sempre visível** + aviso "dados fictícios" no banner fixo.
- **Call nativa bloqueada**: `/demo/dashboard/atendimentos` mostra "Ligação nativa indisponível na demo" com tooltip — nunca abre WebRTC/signaling real (`demo-feature-flags.ts`).
- **noindex** na demo interna (`robots: { index: false }` no layout); a landing continua indexável.

## Interatividade (estado local + localStorage)

Ações que funcionam de verdade na demo, persistidas em `localStorage` (`nutriopus-demo-state-v1`):
adicionar peso, criar nota clínica no prontuário, concluir lembrete, registrar refeição no diário, marcar item de compras, enviar mensagem no chat (com resposta automática mockada), copiar lista de compras. O botão **Resetar demo** (banner) limpa o storage e restaura os dados iniciais.

## Alternância de visão

Botão fixo no banner: no dashboard → "Ver como paciente" (`/demo/portal`); no portal → "Ver como nutricionista" (`/demo/dashboard`). Também há botão "Sair da demo" (volta para `/`).
